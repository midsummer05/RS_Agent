# 受约束的 LLM 规划策略

## 为什么调整

旧实现允许 LLM 在预处理、解译、后处理和 QA 四个阶段自由生成连续参数。此前完整评测显示这会让模型猜测 NDWI 阈值或 SAR 分位数，平均 IoU 从规则的 0.300853 降至 0.217172。

## 当前策略

1. LLM 在预处理、解译、后处理和 QA 四个阶段都生成计划；报告阶段固定规则执行。
2. LLM 可匹配合法工具并规划参数，但参数必须逐值匹配 Tool Registry 中有限、审查过的配置档案。
3. 每个 LLM 计划自动附加兼容的规则回退工具；非法输出修复一次，仍失败则回退规则路由。
4. 影像预处理写入不含像素和标签的路由诊断：有效像元比例、NDWI/VV 分位数、有限候选覆盖率。
5. 所有模型计划均经过 JSON Schema、工具契约和参数档案校验后才可越过工具边界。

这恢复了开发文档要求的四个受约束规划点，同时避免自由数值调参造成的不可审计参数漂移。

## 本次验证

独立烟测已验证：4 个案例共 16 次真实模型 HTTP 200，四个规划点均有合法计划且未回退。完整 24 例复验也已完成：96 次 HTTP 200、96 个合法规划点、无回退；规则/受约束 LLM 的平均 IoU 为 0.300853/0.328561，完成率为 83.33%/95.83%。完整证据与限制见 [Phase 4 验收记录](PHASE4_ACCEPTANCE.md)。

## 何时增加工具分支

在实现至少两条可实际执行、各自有离线基准和明确适用条件的工具分支后，例如经验证的 SAR Otsu 与自适应阈值分支，或云遮蔽处理与标准 NDWI 分支，LLM 的工具匹配空间才会扩大。届时应：

- 给每个分支固定参数配置及适用条件；
- 以不含真值的诊断特征作为模型上下文；
- 保留规则默认分支和回退；
- 重新运行 24 例对照，要求 LLM 选择分支的指标不低于默认基线，再推广。
