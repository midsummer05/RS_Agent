# 遥感影像解译 Agent：简历建议与面试讲解

## 推荐项目标题

**遥感影像解译 Agent｜可恢复、可审计的多阶段地理空间工作流**

## 简历项目描述（推荐 3--4 条）

- 设计面向光学与 SAR 影像水体提取的 Agent 工作流，以固定五阶段状态机编排预处理、解译、后处理、质检和报告；控制流与影像 artifact 数据流解耦。
- 基于 SQLite checkpoint、内容寻址 artifact store 和幂等 step key 实现断点恢复；核心阶段中断后复用已验证产物，避免重复执行成功步骤。
- 构建受 Pydantic JSON Schema 与工具契约双重约束的 Planner：DeepSeek 仅处理影像元数据、产物摘要与允许工具，非法计划自动修复一次并回退规则路由。
- 实现光学 NDWI/RGB 回退与 SAR 去斑-自适应阈值基线，输出 GeoTIFF 掩膜、GeoJSON、统计 JSON 和报告；提供审批、trace 回放、失败注入与规则/LLM 路由评测 Harness。

## 技术栈

Python 3.11、FastAPI、Pydantic、SQLite、Docker Compose、Rasterio、NumPy、SciPy、Pillow、SSE、pytest、Ruff、DeepSeek OpenAI-compatible API。

## 90 秒项目讲解

“这个项目不是把遥感算法包装成聊天机器人，而是解决长耗时影像任务如何可靠地由 Agent 编排。工作流生命周期固定为五阶段，每个阶段完成后先写入不可变 artifact，再落 SQLite checkpoint。因此 worker 在核心解译后中断时，重启会从最近成功阶段继续，而不会重复计算。

模型只负责阶段内工具与参数选择。它看不到原始像素，只看到元数据、质量摘要和可调用工具；输出先经过 JSON Schema，再经过工具契约验证，失败会修复或回退到规则路由。系统还记录 plan、工具参数、耗时、错误和审批，使结果可回放。最后，我把评测拆成正式带标注案例与开发冒烟案例，对比规则和 LLM 路由的遥感指标与工程指标。”

## 高频追问与回答要点

### 为什么不用 LLM 直接读影像？

影像体积大、可复现性差且成本不可控。像素处理由确定性工具完成；LLM 只做可验证的调度和参数选择。

### 如何保证恢复不重复算？

成功 artifact 用哈希标识，checkpoint 只保存 URI、哈希和摘要；恢复时以已完成阶段和幂等 key 跳过成功步骤。

### LLM 输出错误怎么办？

先做 Pydantic JSON Schema 校验，再校验阶段、传感器、任务和参数范围；失败修复一次，仍失败走规则路由，未验证计划不会触发工具调用。

### 评测如何避免数据泄漏或手工调参？

正式评测集版本化，manifest 记录来源和许可；开发 smoke 数据不计正式指标，参数按传感器/任务路由而非逐案例手工调整。
